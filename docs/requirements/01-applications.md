# 01. Applications

Status: **Built**

- Create, view, edit and delete job applications. Each has a company, role name, IC or management flag, status, listing URL, expected monthly gross salary in ILS, source, notes and applied date.
- Companies are shared between applications and deduplicated by case-insensitive name. Each company has a size (early-stage startup, startup, scale-up, corporate), public or private flag, website and location. Companies can also be managed on their own, including ones with no application, on the Companies page (see [11](11-companies.md)).
- **Status pipeline:** to apply → applied → coffee chat → HR screening → phone → technical → home assignment → onsite → managerial → final → offer → accepted. The closed outcomes are accepted, rejected, withdrawn and ghosted.
- **Status groups.** Every status belongs to exactly one group, which says how far the application got:

  | Group       | Statuses                                                                                       | Meaning                                                                                        |
  | ----------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
  | **Initial** | to apply, applied                                                                              | Nothing has happened with the employer yet: not applied, or applied and no interview.          |
  | **Active**  | coffee chat, HR screening, phone, technical, home assignment, onsite, managerial, final, offer | The process is moving: an interview is scheduled or has happened, or an offer is on the table. |
  | **Closed**  | accepted, rejected, withdrawn, ghosted                                                         | The process ended.                                                                             |

  Grouping is by the status shown, so an application with a scheduled or held round is always Active.

- **Status: milestones you set, rounds that come from interviews.** The status shown for an application (list, pipeline, stage bar, filters, counts) answers "where does this stand right now?".
  - **Milestones are set by hand:** to apply, applied, offer and the closed outcomes (accepted, rejected, withdrawn, ghosted). Each change is recorded in the status history.
  - **Rounds are never set on their own.** Coffee chat, HR screening, phone, technical, home assignment, onsite, managerial and final exist only as interviews (see [02](02-contacts-and-interviews.md)). Choosing a round in the status dropdown or the pipeline asks when it takes place (default now, past or future) and adds that interview. There is no round status without an interview behind it.
  - **What is shown:**
    1. **Offer and closed outcomes always win.** An application with an offer or closed shows that, whatever interviews exist, and a closed application never shows an upcoming round.
    2. **An upcoming interview wins.** Otherwise, if an interview with a stage is scheduled in the future, its stage is shown (for example Technical), with the date and time under the badge. The round that just passed no longer matters once the next one is lined up. If several are scheduled, the earliest counts.
    3. **Otherwise the last round held.** With nothing scheduled, the latest past interview with a stage is shown, so after a round and while you wait for the company, it keeps showing that round.
    4. **Otherwise the milestone** (to apply or applied).
  - **It follows the calendar.** Removing or moving an interview changes the status accordingly (removing the only interview falls back to applied or to apply). The status can go back to an earlier stage when the next scheduled round is earlier than one already held (for example another phone call after a technical interview).
  - **Every interview type has a stage except "other"** (home assignment review counts as home assignment). An "other" interview never changes the status, but when it is the next thing scheduled, the date line under the badge names it (for example "Other · 12 Nov, 10:00").
  - Going back to to apply or applied is only offered while the application has no interviews.
  - **Open** means Initial or Active (everything not closed); the rest of the app uses it for "still in play" (action queue, dashboard KPI, Companies counts).

- **Date display:** everywhere the app shows a date, today, tomorrow and yesterday appear as "Today", "Tomorrow" and "Yesterday" (with the time after a comma when there is one); any other day shows the date. Date pickers in forms keep the plain date.
- **Repeated rounds:** the same round can happen more than once (for example two phone interviews, one after the other). "Add another \<round\>" on the application page adds one more interview of that type; nothing needs a special flag. The API and the assistant tool `change_application_status` also add an interview when given a round (`interviewAt` optional, default now). A repeated round never changes the applied date.
- **History: the whole flow in one list.** The status history on the application page shows every step in date order: to apply, Applied (at the applied date, even if nothing was recorded when it was typed in), every interview round under its stage name (Coffee chat, HR screening, Phone interview, …; future ones dashed and labelled Scheduled), and the later milestones (offer, accepted, rejected, withdrawn, ghosted, and a re-apply after a close). Repeated rounds each show. The record itself keeps only the milestone changes; rounds come from the interviews, so nothing is duplicated. The applied date is set automatically the first time an application leaves "to apply" or gets its first interview.
- **Existing data:** applications that had a round stored as their status were moved over once (a one-off script, since removed): they are set to applied, and a round with no interview behind it gets a matching placeholder interview (time unknown), so no round disappears. If the application already had an interview with a stage, nothing is added: that interview says where it stands.
- **Views:** the applications page has a Table | Timeline switch (the optional gamification layer adds Pipeline, see [08](08-gamification.md)).
  - **Timeline** (`/applications/timeline`) shows the interview rounds of all applications at once, in chronological order, as a vertical line grouped by day (Today, Tomorrow, Yesterday or the date) with a "Now" marker between rounds already held and upcoming ones. Each round shows time, type, company, role and location, and is a link to its application page. History is limited to the past 7 days; every planned round is shown, however far ahead. Rounds without a real time (placeholder interviews, see Existing data) are left out because they have no place on a calendar. Closed applications' rounds are included.
- In the applications list the Interviews column counts the interview rounds held so far: one per past interview with a stage, so two phone calls count as two. The status cell shows the status as read-only text (it is changed from the detail page or pipeline, not inline) and, when a round is scheduled, its date and time below it (there is no separate "Next interview" column). The list can be filtered by status group (a multi-select dropdown: Initial, Active, Closed; Initial and Active selected by default, so all open applications; selecting nothing or all three shows everything), and searched by company or role.
